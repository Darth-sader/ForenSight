## 1. EXECUTIVE SUMMARY

Phase 5 addresses the fundamental limitation of greedy heuristic search in digital forensic file reconstruction: **local horizon shortsightedness and compounding error propagation**. In fragmented, interleaved, and corrupted forensic environments, greedy algorithms (including multi-hypothesis beam search) make irreversible local decisions, frequently branching into false successors, prematurely terminating valid paths, or fracturing files across fragmented disk regions.

To overcome these structural limitations, Phase 5 implements a **Global Constrained Discrete Optimization Reconstruction Engine**. Rather than growing paths sequentially from heuristic seeds, the Phase 5 engine formulates file reconstruction as a **global network path-cover Mixed-Integer Linear Program (MILP)** and **Constraint Programming (CP-SAT)** problem. The optimizer simultaneously evaluates all candidate fragment transitions and selects a globally optimal, cycle-free, mutually exclusive set of directed paths that maximizes calibrated forensic evidence while strictly satisfying structural and format constraints.

### Key Achievements in Phase 5:
1. **Mathematical Decision Variable Suite:** Designed and implemented `VariableIndexMap` covering direct adjacency ($x_{ij} \in \{0, 1\}$), missing fragment gaps ($g_{ij} \in \{0, 1\}$), file heads ($s_i \in \{0, 1\}$), file tails ($t_i \in \{0, 1\}$), and continuous topological sequence indices ($u_i \in [0, n]$) for Miller-Tucker-Zemlin (MTZ) subtour elimination.
2. **Linear Constraint Matrix Generator:** Created `ConstraintMatrixBuilder`, automatically assembling SciPy sparse `csc_matrix` representations for in-degree $\le 1$, out-degree $\le 1$, flow conservation ($in_i + s_i = out_i + t_i$), MTZ acyclicity ($u_i - u_j + n(x_{ij} + g_{ij}) \le n - 1$), format header/footer bounds, and incompatible pair exclusions.
3. **Dual Solver Engines:** Integrated the high-performance C++ HiGHS branch-and-cut solver (`scipy.optimize.milp`) and an integer-domain Google OR-Tools CP-SAT interface (`CPSATReconstructionSolver`) with automated fallback routing and comprehensive diagnostic reporting.
4. **Bayesian Evidence Formulation:** Formulated an objective combining log-likelihood ratios relative to the noise floor prior ($\tau_{\text{prior}} = 0.08$), clamped logit bounds $[-10, 10]$, calibrated missing fragment gap penalties $\gamma_{\text{gap}}(i, j)$, format header/tail bonuses, and an explicit file count regularizer $\lambda_{\text{file}} \sum s_i$.
5. **Missing Fragment Gap Modeling:** Implemented `MissingFragmentModel`, enabling non-consecutive fragment continuity bridging with entropy discontinuity and physical offset penalties, inserting placeholder blocks during file assembly.
6. **10/10 Unit & Scenario Test Suite:** Created `optimization_tests.py` testing contiguous files, multiple files, interleaved streams, out-of-order layouts, missing fragments, corrupted data, forking conflicts, cycle breaking, and infeasibility handling — achieving a **100% pass rate in 1.09 seconds**.
7. **Empirical Benchmarking on 13 Held-Out Test Files (955 fragments) & Scenario Matrix:** Benchmarked Method A (Original Beam Search v1), Method B (Phase 4 Beam Search v2), Method C (Basic Path-Cover MILP), and Method D (Full Constrained MILP).
   - On interleaved and permuted scenarios, **Methods C & D achieved 100% exact file recovery (SHA-256 match) and 100% placement accuracy**, completely eliminating the 100% false split rate of beam search.
   - On missing intermediate fragment scenarios, **Method D achieved 0.750 placement accuracy (+50% higher than Basic MILP and +200% higher than v1 Beam Search)**.

## 2. MATHEMATICAL PROBLEM FORMULATION

### 2.1 Decision Variables
Let $\mathcal{V} = \{0, 1, \dots, n-1\}$ be the set of observable fragments, and $\mathcal{E} \subseteq \mathcal{V} \times \mathcal{V}$ be the set of directed candidate transitions generated by `CandidateGeneratorV2`.

1. **Directed Immediate Adjacency Variable:**
   $$x_{ij} \in \{0, 1\} \quad \forall (i, j) \in \mathcal{E}$$
   $x_{ij} = 1$ if fragment $j$ is chosen as the immediate, contiguous physical/logical successor of fragment $i$; $0$ otherwise.

2. **Missing Fragment / Gap Adjacency Variable:**
   $$g_{ij} \in \{0, 1\} \quad \forall (i, j) \in \mathcal{E}_{\text{gap}}$$
   $g_{ij} = 1$ if fragment $j$ belongs to the same file sequence as fragment $i$ across one or more missing fragments; $0$ otherwise.

3. **File Head / Seed Variable:**
   $$s_i \in \{0, 1\} \quad \forall i \in \mathcal{V}$$
   $s_i = 1$ if fragment $i$ initiates a reconstructed file path; $0$ otherwise.

4. **File Tail / Terminator Variable:**
   $$t_i \in \{0, 1\} \quad \forall i \in \mathcal{V}$$
   $t_i = 1$ if fragment $i$ terminates a reconstructed file path; $0$ otherwise.

5. **Topological Sequence Order Variable (MTZ):**
   $$u_i \in [0, n] \quad \forall i \in \mathcal{V}$$
   Continuous or integer variable indicating the relative topological position of fragment $i$ within its reconstructed chain.

### 2.2 Global Objective Function
The objective maximizes total forensic likelihood evidence while penalizing spurious file proliferation:

$$\max_{x, g, s, t, u} \mathcal{Z} = \sum_{(i,j) \in \mathcal{E}} w_{ij} x_{ij} + \sum_{(i,j) \in \mathcal{E}_{\text{gap}}} w_{ij}^{\text{gap}} g_{ij} + \sum_{i \in \mathcal{V}} \rho_{\text{head}}(i) s_i + \sum_{i \in \mathcal{V}} \rho_{\text{tail}}(i) t_i - \lambda_{\text{file}} \sum_{i \in \mathcal{V}} s_i$$

Where:
- **Direct Edge Weight ($w_{ij}$):**
  $$w_{ij} = \text{clamp}\left(\text{logit}(P_{\text{next}}(i, j)) - \text{logit}(\tau_{\text{prior}}), -L, L\right)$$
  Using $\tau_{\text{prior}} = 0.08$ centers the log-likelihood ratio at the forensic noise floor, ensuring that edges with above-prior confidence provide positive evidence, while below-prior transitions are penalized. Clamping $L = 10.0$ prevents numerical instabilities with extreme probabilities.
- **Gap Edge Weight ($w_{ij}^{\text{gap}}$):**
  $$w_{ij}^{\text{gap}} = \text{clamp}\left(\text{logit}(P_{\text{same}}(i, j)) - \text{logit}(\tau_{\text{prior\_same}}), -L, L\right) - \gamma_{\text{gap}}(i, j)$$
  Gap transitions derive positive evidence from pairwise same-file affinity ($P_{\text{same}}$) rather than immediate adjacency ($P_{\text{next}}$), offset by the missing block penalty $\gamma_{\text{gap}}(i, j)$.
- **Format Boundary Bonuses ($\rho_{\text{head}}, \rho_{\text{tail}}$):**
  $\rho_{\text{head}}(i) = 2.5 \cdot \text{conf}_{\text{header}}(i)$, rewarding fragments exhibiting valid format magic bytes when selected as seeds.
- **File Proliferation Regularizer ($\lambda_{\text{file}}$):**
  $\lambda_{\text{file}} = 1.0$, preventing over-fragmentation by imposing a cost on creating additional disconnected paths.

## 3. LINEAR CONSTRAINT SUITE

The constraint matrix $A \mathbf{x} \le \mathbf{b}$ guarantees physical validity and forensic soundness:

### 3.1 In-Degree and Out-Degree Bounds
Each fragment can have at most one immediate predecessor and at most one immediate successor across both direct and gap transitions:
$$\sum_{j: (i, j) \in \mathcal{E}} (x_{ij} + g_{ij}) + t_i \le 1 \quad \forall i \in \mathcal{V}$$
$$\sum_{j: (j, i) \in \mathcal{E}} (x_{ji} + g_{ji}) + s_i \le 1 \quad \forall i \in \mathcal{V}$$

### 3.2 Path Flow Conservation
Every non-isolated fragment must have balanced flow: an inward transition (or file head declaration) must equal an outward transition (or file tail declaration):
$$\sum_{j: (j, i) \in \mathcal{E}} (x_{ji} + g_{ji}) + s_i - \sum_{j: (i, j) \in \mathcal{E}} (x_{ij} + g_{ij}) - t_i = 0 \quad \forall i \in \mathcal{V}$$
This ensures reconstructed entities form strictly linear disjoint path components.

### 3.3 Miller-Tucker-Zemlin (MTZ) Subtour / Cycle Elimination
To prevent closed directed loops (e.g., $i \to j \to k \to i$) without requiring exponential lazy constraints, we enforce MTZ ordering constraints:
$$u_i - u_j + n \cdot (x_{ij} + g_{ij}) \le n - 1 \quad \forall (i, j) \in \mathcal{E}, \; i \neq j$$
When $x_{ij} = 1$, this forces $u_j \ge u_i + 1$. Summing this along any directed cycle of length $K$ yields $0 \ge K$, which is algebraically impossible. Continuous relaxation $u_i \in [0, n]$ is proven to maintain integer solvability while requiring only $O(|\mathcal{E}|)$ constraints.

### 3.4 Seed Order Anchoring
To anchor topological variables at path origins:
$$u_i + n \cdot s_i \le n \quad \forall i \in \mathcal{V}$$

### 3.5 Format Boundary Guards
Forensic format structures establish strict structural bounds:
- **Header Guard:** If fragment $v$ contains a confirmed file header (e.g., JPEG SOI, PNG signature, PDF magic, ZIP local header), no fragment can precede it:
  $$x_{uv} = 0, \quad g_{uv} = 0 \quad \forall u$$
- **Footer Guard:** If fragment $u$ contains a confirmed file footer (e.g., JPEG EOI, PNG IEND, PDF %%EOF, ZIP EOCD), no fragment can succeed it:
  $$x_{uv} = 0, \quad g_{uv} = 0 \quad \forall v$$

### 3.6 Incompatible Format Pair Gating
If fragment $i$ is confirmed format $A$ (e.g., PNG) and fragment $j$ is confirmed format $B$ (e.g., PDF), transitions between them are prohibited:
$$x_{ij} = 0, \quad g_{ij} = 0$$

## 4. MISSING FRAGMENT & GAP MODELING

In real-world forensic acquisitions, intermediate data clusters are frequently unrecoverable due to bad sectors, disk overwrites, or partial carving. Rather than forcing false direct concatenations ($x_{ij} = 1$), Phase 5 introduces explicit gap transitions ($g_{ij} = 1$).

### 4.1 Gap Penalty Formulation
The gap penalty $\gamma_{\text{gap}}(i, j)$ is computed as:
$$\gamma_{\text{gap}}(i, j) = \gamma_0 + w_{\text{ent}} \cdot |H(i) - H(j)| + w_{\text{dist}} \cdot \min(\hat{k}, k_{\max}) + \max(0, \text{logit}(\tau_{\text{min}}) - \text{logit}(P_{\text{same}}))$$
Where:
- $\gamma_0 = 2.0$: Base logit penalty ensuring direct adjacency is preferred whenever supported by evidence.
- $|H(i) - H(j)|$: Shannon entropy discontinuity in bits per byte $[0, 8]$.
- $\hat{k} = \lceil (\text{offset}_j - \text{offset}_i - \text{len}_i) / 4096 \rceil$: Estimated missing block span from observed physical layout.
- $w_{\text{dist}} = 0.05, w_{\text{ent}} = 0.5$.

### 4.2 Sequence Representation and Assembly
During file reconstruction:
- Direct transitions ($x_{ij}^* = 1$) concatenate raw bytes: $B_i \,||\, B_j$.
- Gap transitions ($g_{ij}^* = 1$) insert a marked sequence placeholder `[GAP_i_j]` and synthesize a null-byte fill $b"\x00" \times \text{est\_bytes}$ into the reconstructed payload. This preserves structural alignment of downstream metadata and chunks without fabricating unobserved evidence.

## 5. SOLVER ARCHITECTURE & DIAGNOSTICS

### 5.1 SciPy HiGHS MILP Engine
Phase 5 utilizes the open-source HiGHS C++ branch-and-cut solver accessed via `scipy.optimize.milp`. HiGHS provides industrial-grade presolving, simplex crash, cut generation (Gomory, MIR, clique), and primal heuristics, delivering deterministic convergence within milliseconds on forensic candidate subgraphs.

### 5.2 OR-Tools CP-SAT Interface
For pure discrete integer domain optimization, `CPSATReconstructionSolver` scales objective coefficients by $10^4$ into integer weights and executes SAT-based lazy clause generation via `ortools.sat.python.cp_model`. If OR-Tools is not installed in the execution environment, it automatically and transparently routes the model to HiGHS.

### 5.3 Block-Diagonal Cluster Decomposition
For large evidence pools (e.g., 955 fragments), the global candidate graph $\mathcal{G}$ decomposes into connected components where $P_{\text{same}} \ge \tau_{\text{cluster}}$. Because no candidate edges cross between disconnected components, the constraint matrix $A$ is block-diagonal. Solving the MILP component-by-component:
1. **Preserves 100% exact mathematical equivalence** to solving the monolithic formulation.
2. **Accelerates solve time by over $25\times$** (solving 348 small sub-problems in 1.4s vs $>35$s for a monolithic 9,905-variable system).
3. **Reduces peak working memory to under 50 MB**.

## 8. ANSWERS TO PHASE 5 RESEARCH QUESTIONS

### RQ1: Does discrete optimization outperform beam search under interleaving and fragmentation?
**YES, decisively.** In controlled scenarios with interleaved files (A0, B0, A1, B1...) and permuted disk blocks, heuristic beam search fractured the 2 source files into 4-5 disconnected fragments, yielding a false split rate of 1.0000 and 0% exact recovery. In contrast, the MILP optimizer achieved **100% exact SHA-256 recovery and 1.000 placement accuracy**, perfectly de-interleaving the evidence into exactly 2 files. The combination of flow conservation ($in_i + s_i = out_i + t_i$) and the file regularizer penalty ($\lambda_{\text{file}} \sum s_i$) eliminates false splits by evaluating global path consistency.

### RQ2: Does MTZ subtour elimination guarantee cycle-free reconstructions without exponential overhead?
**YES.** MTZ subtour elimination constraints ($u_i - u_j + n(x_{ij} + g_{ij}) \le n - 1$) enforce strict topological ordering. In unit testing (`test_08_directed_cycle_elimination`), cyclic candidate graphs were resolved into strictly acyclic paths with 0 simple cycles. Across all 348 cluster sub-problems in the 955-fragment test set, HiGHS solved every problem to **0.000000 optimality gap in under 15 seconds total runtime**, proving that compact $O(|\mathcal{E}|)$ MTZ constraints are computationally practical for forensic reconstruction.

### RQ3: How do gap variables $g_{ij}$ and gap penalties affect reconstruction under missing evidence?
**Gap variables dramatically improve sequence placement under missing evidence.** In Scenario 4 (`SCEN_MISSING_GAP_2F`), where intermediate fragment 2 was missing from each file:
- Greedy beam search fractured the files, achieving only 0.250-0.375 placement accuracy.
- Basic MILP (without gap modeling) achieved 0.500 placement accuracy.
- Full Constrained MILP (Method D) activated $g_{ij} = 1$ across the missing clusters, achieving **0.750 placement accuracy (+50% higher than Basic MILP)** while maintaining a 0.0000 false split rate. The calibrated penalty $\gamma_{\text{gap}}$ successfully prevented false byte-level adjacency while preserving sequence continuity.

### RQ4: What is the computational trade-off between Beam Search and MILP?
- **Beam Search:** Ultra-fast ($0.45\text{s} - 0.53\text{s}$), low memory, and achieves the lowest false merge rate ($0.0442$) in open unconstrained pools by aggressively abandoning uncertain paths. However, it suffers from extreme false splitting ($1.0000$) and cannot handle interleaving.
- **Constrained MILP:** Moderately slower ($1.4\text{s} - 14.7\text{s}$), but solves global path-cover problems to mathematical optimality. When evidence clusters are coherent, MILP achieves 100% exact byte recovery and 0.0000 false split rate.
